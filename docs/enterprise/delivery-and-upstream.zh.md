## 仓库与分支职责

本次设计工作在现有 `master` 检出基础上创建本地开发分支 `codex/enterprise-wecom-deepseek`，保留上游历史。已有无关未跟踪文档不属于本次改动。本套文档不创建额外仓库或远程源。

| 规划归属 | 内容 | 升级边界 |
| --- | --- | --- |
| Harness 企业发行 | 原生欢迎页接入、构建标识、profile 及 home 选择、更新源和打包补丁。 | 逐次评审上游合并，按职责分隔补丁。 |
| 独立企业项目 | 后端、管理网页、API schema、外部身份及模型和 UI 插件、企业组合包。 | 后端 API 独立演进，插件声明已验证 Harness 范围。 |
| 企业设计目录 | 本套文档及需求和测试标识。 | 行为变化时更新对应归属文档。 |

独立项目内拟按 `apps/server`、`apps/admin`、`packages/api-contract`、`packages/harness-identity`、`packages/harness-provider`、`packages/harness-ui` 及 `packages/harness-bundle` 组织模块。取得授权后通过企业包和发行流程发布插件产物，避免仅为方便而复制插件源码到上游包中。

<a id="phases"></a>
## 实施阶段

| 阶段 | 产出 | 完成证据／依赖 |
| --- | --- | --- |
| 0：接入验证 | 验证企业微信身份及通讯录权限、实际 DeepSeek Messages/Files 约定。 | 真实测试身份、获准测试费用、模型输出上界及文件和用量 schema；消除生产设计假设。 |
| 1：后端基础 | 校验配置、数据库迁移、身份会话、完整组织快照及管理访问。 | 通过合成边界验收 A、O、S 类组件用例；开放真实入口前仍须完成阶段 0 资格验证。 |
| 2：策略与网关 | 有效策略、Messages 转发、Files 隔离、事务输出额度、用量及审计。 | P、G、F、Q 用例、并发及崩溃恢复、真实上游验证。 |
| 3：桌面插件 | 身份、模型、UI 插件与企业组合包，安全刷新和受管配置。 | 真实 Loader 组合、模型可见快照及员工走查。 |
| 4：桌面发行 | 最少原生补丁、企业应用标识、数据隔离、签名及更新源。 | macOS arm64 打包安装、更新及迁移证据。 |
| 5：试点与发行 | 限定部门试点、监控、备份恢复演练及发行报告。 | 全部 P0 和性能目标；扩大范围前完成产品、安全及运维验收。 |

新增行为采用测试先行实现，并评审各可独立交付改动。用例由[测试文档](test-cases.zh.md)定义，本表仅描述顺序，不重复测试步骤。本次文档任务不执行这些后续测试。

本地开发使用独立显式入口、合成企业和员工 ID、回环 HTTPS 以及隔离的 PostgreSQL 集群，在相同会话、授权和组织发布链路上运行，不使用真实企业微信凭据或模型调用。ENT-034～037 分别登记协议修正、同步运行时、本地环境和真实 Loader 开发组合。ENT-023～026 可基于该组件基线推进；发行批准和试点前仍须完成 ENT-022 安全审批及 ENT-005 真实资格验证。

<a id="upstream"></a>
## 上游集成

在专用集成分支选择明确的上游发行或标签。将上游历史合入企业发行版，解决少量原生补丁，再适配 API 变化涉及的外部插件消费方。采用明确的合并策略，保留连续历史。

- 检查上游对 DeepSeek 共享适配器、profile 加载、插件兼容、客户端 slot、账号及原生欢迎页、数据格式和更新配置的修改。
- 针对候选上游和插件组合运行企业关键回归，覆盖登录、撤权、组织策略、流式工具与推理、Files 所有权、额度、已有会话及打包。
- 在发行 manifest（元数据清单）中固定上游发行、企业补丁版本、插件及组合包版本、企业 API 主版本及数据库和会话兼容信息。校验摘要及已验证模型能力记录于发行产物，不在维护文档中手写提交哈希。
- 阻止不兼容的插件与运行时组合，不以兼容豁免作为发行流程。Harness API 尚未稳定，即使源码合并无冲突，每次更新也须验证。

在受支持的桌面版本窗口内保持服务端 API 向后兼容，使后端修复可独立发行。并行支持窗口及最低版本由发行 manifest 定义。版本头用于兼容管理，无论版本字符串为何，授权始终由服务端执行。

<a id="release"></a>
## 发行与恢复

使用企业自己的应用 ID、产品名、签名及公证身份、更新源与强制更新策略。当前[生产更新配置](../../apps/desktop/scripts/desktop-auto-update-environment.mjs)固定官方源，因此企业发行版须明确支持可配置的企业源。企业发行渠道独立于官方 nightly。

启动前选择独立 Electron userData，在员工 Host 启动前选择按身份隔离的 Harness home；登录阶段使用不含凭据的引导空间。Finder 启动不依赖 shell 变量来选择路径。不自动导入个人凭据或对话。另行批准导入功能时须定义支持格式、权限、复制行为及恢复方式。

首期在维护窗口部署：停止新接纳，排空活动请求或标记不确定，备份数据，执行仅前向迁移，验证就绪后恢复流量。每日全量备份配合持续 WAL 归档，目标 RPO 为 15 分钟、经演练的 RTO 为四小时；发行前确认托管支持并执行恢复验证。

仅当前一个构建支持现有 schema 和会话格式时才允许应用回滚，否则将已验证备份恢复到隔离环境。开放前轮换部署侧认证世代，撤销恢复出的全部设备和管理员会话，作废全部恢复出的登录尝试，取得新组织快照，并根据独立留存的安全记录复核管理员授权和人工停用状态。无法确认安全状态的员工保持冻结。流量恢复前核对预留及潜在上游费用。旧程序拒绝不支持的较新数据，不承诺自动 schema 降级。

<a id="inputs"></a>
## 部署输入

| 责任方 | 必需决策或输入 |
| --- | --- |
| 企业微信管理员 | CorpID、AgentID、受保护密钥引用、应用可见范围、通讯录字段、可信网络配置、回调域及测试账号。 |
| 模型账号负责人 | 企业 DeepSeek 凭据引用、实际 Messages/Files 能力、获准模型 ID、输出与推理上限、计价及测试费用。 |
| 产品及财务负责人 | 月度额度、企业时区、成本部门归属、不确定用量对账负责人及报表保留周期。 |
| 运维及安全负责人 | 托管环境、PostgreSQL 备份及 WAL 支持、HTTPS 证书、管理员允许名单、审计保留、监控及故障联系人。 |
| 桌面及发行负责人 | 企业应用标识、Keychain 访问、Apple 签名及公证、包分发、更新域、试点设备及受支持版本窗口。 |

这些输入阻断生产接入或发行，不阻断本套设计文档创建。不得索取或粘贴真实密钥到文档中。决策修改其归属文档，批准及证据通过发行流程记录。

## 开发备注

独立企业仓库位置、具体包命名空间、托管环境及保留周期在实现前确定；已同意的架构不依赖这些名称。
