## 环境与证据

准备一个测试企业，包含父子部门、两个平级部门、员工 A/B、多部门员工、停用员工、管理员、普通员工和范围外身份。使用隔离 PostgreSQL、确定性时钟、可编排的企业微信边界以及真实 HTTP Messages/Files 模拟服务。组合测试保留真实 Harness Loader、模型提供方、会话、工具和持久化。

层级：U 为单元，I 为数据库或 HTTP 集成，C 为真实 profile 组合，R 为真实企业微信或 DeepSeek 集成，D 为 macOS 打包客户端。P0 阻断发行，P1 覆盖运维质量。证据包括脱敏输入、请求次数、账本及数据库断言、外部观察的工具效果及必要截图。

以下用例初始均为未执行。实现后在发行证据中记录运行标识、准确版本、环境、通过与否、产物和缺陷链接；mock 结果不得标记为真实服务或签名发行验证。

## 额度与故障

| 用例／需求 | 优先级 | 前置条件与步骤 | 预期结果 | 层级 |
| --- | --- | --- | --- | --- |
| Q01 / PR-06 | P0 | 请求额度分别等于、小于及大于可用输出额度。 | 正确接纳；超额预留在派发前拒绝。 | U/I |
| Q02 / PR-06 | P0 | 多名员工经两个后端实例并发 100 次接纳，竞争低额共享预算。 | 企业、员工及部门桶均不超额，预留同时提交或回滚。 | I |
| Q03 / PR-06 | P0 | 额度充足时发起第三个调用；终止一个无最终用量的操作后重试。 | 第三个起初受限；并发槽恢复，但不确定额度预留继续保留。 | I/C |
| Q04 / PR-06 | P0 | 重复发送有效终态用量，或并发对账。 | 每请求仅一次扣量及释放，账本证据不可变。 | I |
| Q05 / PR-06,12 | P0 | 派发后取消或断线，未取得最终用量，随后对账。 | 尝试终止上游并保留不确定预留；产生脱敏告警，对账后清除。 | I/C |
| Q06 / PR-06,12 | P0 | 分别在派发前、派发窗口和收到终态后崩溃。 | 可证明未发送的工作释放；歧义请求保持不确定；结算唯一。 | I |
| Q07 / PR-06 | P0 | 不确定请求超过 24 小时后，再提供可信实际用量。 | 明确估算扣量后执行一次受审计差额调整，无重复退款。 | U/I |
| Q08 / PR-06 | P0 | 派发后以相同幂等键提交相同或不同请求体。 | 不再次执行；内容改变时返回 409。 | I |
| Q09 / PR-06 | P0 | 流中跨月、修改价格或调岗，再将预算调低至已结算加预留以下。 | 请求快照固定，新周期原子初始化，无效调低返回 409。 | U/I |
| Q10 / PR-05,06 | P0 | 使用真实模型测试包含推理和图片输入的输出上限。 | 观测输出不超过预留；无法验证上界则阻止模型启用。 | R |
| Q11 / PR-06,12 | P0 | 价格或缓存数据缺失；接纳时数据库故障并恢复。 | 金额不可用或估算；故障不派发，产生脱敏告警，恢复后清除。 | I |
| Q12 / PR-05,06 | P0 | Messages 结束时输出用量缺失、非整数、为负、回退或超过预留。 | 不虚构零结算；请求转不确定，上界违规停用模型，保留事件证据。 | I/C |

<a id="release"></a>
## 发行验收

本矩阵包含 61 个用例：57 个 P0 和四个 P1；PR-01 至 PR-12 均有覆盖。先实现单元及数据库约束，再执行真实 profile 用例及试点企业走查。企业后端行和分支覆盖率至少 80%；修改 Harness 包代码时遵循仓库按文件覆盖规范。

发行要求全部 P0 用例及产品性能目标通过，无未解决的严重或高风险安全缺陷，并提供真实企业微信和实际企业 DeepSeek Messages/Files 凭据的验证证据。跳过的外部测试属于未验证。付费运行前记录额度及预估上游费用，并取得执行授权。

<a id="dev-note"></a>
## 开发备注

自动化 fixture（测试前置数据）仅使用合成用户和文件。各测试负责自身临时文件、端口、会话和上游清理。快照测试断言模型可见及会话行为，非会话 GUI 与后端行为使用所属模块的预期输出。
