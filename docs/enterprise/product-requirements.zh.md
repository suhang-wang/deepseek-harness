# 企业版产品需求

[English](product-requirements.md) | 中文

<a id="summary"></a>
## 摘要

员工使用企业微信身份登录，无需接触企业 API Key 即可使用获准的 DeepSeek 模型。管理员同步授权组织、配置访问权限和输出额度，并查看用量。本页为[设计状态](README.zh.md)下的需求参考。

<a id="scope"></a>
## 用户与范围

| 角色 | 权限 |
| --- | --- |
| 员工 | 在桌面端登录退出、仅查看本人身份、部门路径、成本部门、有效模型和额度，并运行本地 Harness 任务。 |
| 企业管理员 | 通过管理网页管理授权员工、已验证模型策略、额度、会话、同步、用量报表和审计记录。 |
| 企业所有者 | 执行管理员操作，并额外授予或撤销管理员及所有者权限，轮换服务端 DeepSeek API Key。 |

首位所有者先通过企业微信登录，再输入由明确的服务端操作生成、与本人绑定且短期有效的一次性初始化口令。口令仅在系统从未初始化时可用；日后即使所有者全部丢失也不可重新使用，新增授权须由所有者操作或经过单独审计的运维恢复。普通员工无法进入管理网页，部门负责人不会自动获得管理权限。本轮使用企业微信浏览器会话，不加入通行密钥二次验证。首期平台为 macOS arm64，其他桌面目标需单独完成发行验证。

首期包含：单企业登录、授权部门树与成员关系、员工生命周期、DeepSeek Messages 流式调用与本地工具及推理、受支持的图片文件路径、模型设置、输出额度、用量估算、审计和企业更新。首期范围之外：多租户 SaaS、其他模型厂商、人事资料回写、审批流程、知识库、集中保存对话及无人值守远程控制员工设备。

## 需求清单

以下需求均为首期必需项。[测试参考](test-cases.zh.md)将各标识映射到具体验收用例，实现规则由[技术设计](technical-design.zh.md)负责。

| 标识 | 需求 | 可观察的验收结果 |
| --- | --- | --- |
| PR-01 | 企业微信登录 | 只有获授权且启用的员工获得桌面会话；取消、过期和重试均有明确结果。 |
| PR-02 | 组织同步 | 导入授权部门树和员工，展示同步时间、范围、数量、失败原因及手动重试。 |
| PR-03 | 成员关系与成本部门 | 保留多部门归属，每人有唯一且有效的成本部门；归属未确定时阻止模型调用。 |
| PR-04 | 模型策略 | 仅管理已完成资格验证的企业模型及企业、部门、员工限制，可预览最终模型、默认值和生效原因。 |
| PR-05 | DeepSeek 网关 | 流式输出、工具执行循环、推理重放及支持的图片均通过企业网关正常工作。 |
| PR-06 | 额度与用量 | 预留并结算输出 token 额度，并发下不超额；区分已确认、预留及不确定用量。 |
| PR-07 | 访问回收 | 退出、会话撤销、停用及已确认移除均阻止后续网关请求。 |
| PR-08 | 数据与凭据保护 | 企业密钥加密保留在服务端，管理读取接口不返回明文；员工文件访问相互隔离；关闭可选的官方上传。 |
| PR-09 | 管理与审计 | 绑定且一次性的初始化完成后才授予首位所有者；拒绝员工访问管理接口，仅所有者可授权和轮换密钥，并审计特权操作。 |
| PR-10 | 桌面发行 | 可安装有独立标识、数据目录及企业更新渠道的客户端。 |
| PR-11 | 上游兼容 | 固定经过验证的上游、插件及 API 组合，升级前验证已有会话数据。 |
| PR-12 | 运维与故障恢复 | 提供可处理的健康、组织过期、上游及账本不确定告警，并验证恢复路径。 |

<a id="flows"></a>
## 产品流程与页面

员工首次使用：打开企业版应用，扫描页面内的企业微信登录二维码，在手机上确认授权后自动进入工作区。二维码不可用时可改用系统浏览器。员工尚未登录也可出现在已同步的管理目录中。员工停用、成本部门未确定或允许模型为空时，页面展示原因及联系管理员的路径。

日常使用：模型选择器展示最终目录和允许的推理、输出设置。每次模型调用，包括任务标题、压缩（compaction）和 subagent 工作，均计入对应额度。访问缺失或撤销时，本地历史仍可读取，新的企业模型调用不可用。

| 页面 | 必需信息与操作 |
| --- | --- |
| 桌面登录与账号 | 本人企业与员工身份、部门路径、成本部门、会话状态、重试、取消、退出及可处理的错误。 |
| 桌面模型设置 | 允许模型、有效默认值、输出上限、额度及策略说明；企业端点由后台管理。 |
| 组织与员工 | 部门树、搜索、多部门关系、成本部门、同步状态及停用、撤销操作。 |
| 管理员权限与提供方 | 所有者管理授权并更换 API Key；提交后不能读取密钥明文，页面只展示配置及版本状态。 |
| 策略与额度 | 企业、部门、员工范围，有效策略预览、版本冲突及月度上限。 |
| 用量与审计 | 员工及成本部门聚合、token 分类、估算费用、不确定记录及特权操作。 |
| 系统状态 | 组织数据新鲜度、网关健康、上游访问、兼容要求及失败后台任务。 |

<a id="policy-experience"></a>
## 策略体验

企业、所属部门及员工的显式限制按保守规则组合。界面解释生效限制，不会静默替换模型。成本归集使用唯一的服务端成本部门；显示多个部门关系不会让一次请求同时记入多个平级部门。

额度以生成的输出 token 计量，包括经验证的上游协议所计入的推理 token。管理员配置有限的企业、员工和成本部门月度额度。输入、缓存 token 统计与带版本的价格用于金额估算，上游账单作为对账依据。不确定用量明确展示，不能显示为已确认的零扣量。

模型列表不能启用未经资格验证的 DeepSeek 模型，首个获准模型为 `deepseek-flash`。密钥更换作用于新接纳调用；已接纳调用及已有文件操作保留所需的凭据版本，直至安全清理。未配置密钥时管理网页仍可使用，模型调用明确显示不可用。

企业发行版将获准模型调用导向网关，并移除常规个人密钥配置入口。控制设备的用户仍可运行其他软件或修改本地代码；控制整机全部流量需要另行实施设备或网络管理策略，不属于本期能力。

<a id="acceptance"></a>
## 验收目标

以下数值为建议验收目标，尚无实测结果。试点基线为 1,000 名员工、100 个部门及 40 条并行模型流，每名员工最多同时进行两个调用。

| 领域 | 目标与测量条件 |
| --- | --- |
| 撤权 | 后台撤销事务提交后拒绝新的接纳，已开始的流在五秒内终止。 |
| 企业微信变化 | 每 15 分钟轮询；分别计算发现延迟和后台执行延迟。同步失败触发告警，不计作已完成生命周期处理。 |
| 组织可用性 | 开放使用前须有首次完整授权快照；快照超过 60 分钟时拒绝新登录与模型调用。 |
| 网关开销 | 试点基线下接纳额外延迟 p95 不超过 200 毫秒，转发延迟 p95 不超过 50 毫秒；排除上游生成及人工登录时间。 |
| 正确性 | 全部 P0 用例通过，无未解决的严重或高风险安全缺陷，无重复结算及跨员工文件泄露。 |
| 验证 | 全员发行前须提供真实企业微信、真实 DeepSeek Messages/Files、已签名 macOS 安装、更新及迁移证据。 |
